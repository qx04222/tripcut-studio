# 标注依据(manifest.tsv / queries.tsv 怎么来的)

标注人:R18 aiground 车道 agent(2026-09-14)。方法:每条素材在 10% / 35% / 60% / 85% 抽 4 帧看画面,
再在 8/22/36/50/64/78/92% 抽 7 帧**只裁画面下 22%**(字幕区)读烧录字幕。所有判断只依据这些帧。

## 1. 文件名是误导的,一个字都不能信

文件名写的是一段旅行日记(`机场出发` / `登机口` / `落地` / `酒店入住` / `晚餐` / `湖边` / `早餐` / `日落`…),
**画面里一样都没有**。21 条里的 18 条真素材全是同一个品牌短片系列的镜头:
金属台面上的红色信封、iMessage 对话、地下停车场、穿皮衣戴 HJC 头盔的骑手、
多伦多市中心夜景、安大略博物馆、BENDA LFC700 PRO 摩托车、片尾「夜间馆藏 / TORONTO AFTER HOURS / EPISODE 01」。

也就是说:`IMG_0818_晚餐` 里**没有食物**,`IMG_0821_湖边` 里**没有湖**,`IMG_0837_日落` 里**没有日落**。
manifest 的 `subject` 列按画面写(`交通` / `人` / `细节` / `建筑`),不是按文件名。

**这条本身就是一个检测器**:如果哪天八维标签跑出来 `IMG_0818_晚餐 → subject=食物`,
那不是模型看懂了,是**某处在拿文件名当特征**。真值表里那格写的是 `细节|人`,会直接判红。

## 2. DJI 三条是合成彩条,不是航拍

`DJI_0101/0102/0103` 是 ffmpeg 生成的彩条+扫描线测试图(4K HEVC、无音轨),
`~/Movies` 里没有母版(证据见 SOURCES.md §2)。它们**没有语义真值**,
八维 / OCR / 最佳窗五列全写 `*`。保留它们的唯一理由是 4K HEVC / 10 bit 的解码与技术分析路径
—— 真素材里 1080×1920、1920×1080、704×1280 三种都有,但没有 4K,也没有无音轨的。
`queries.tsv` 里给了一条 `彩条测试图` 专门点名它们,用来验证"搜索能不能把非内容素材分出去"。

## 3. `subject` / `shot_size` / `viewpoint` / `function` / `person_state` 的取值

取自 `sidecar/prototypes.json`(版本 `p2-c8-v1`)的受控标签,与 `clip_dimensions` 是同一套词表,
不自造词。一条素材里如果两种标签各占约一半帧(常见,因为每条都是 6–15 s 的多镜头剪辑),
就写 `a|b`,任一算对 —— 这和 `analysis_labels.rs` 的 `motion` 列一个约定。
拿不准的写 `*`(例:`IMG_0823_回程` 全片没有人的动作,`person_state` 写 `*`)。

`viewpoint=俯拍` 只给真正俯视台面/座垫的那几条(0812/0817/0818);
骑行镜头虽然机位低,但视线是平的,写 `平视`,不写 `仰拍`。

## 4. `ocr_expect` 只写"我在帧里亲眼看见的字"

两类:①烧录中文字幕(这套片子的对白全部烧在画面下方);②画面内文字(`BENDA` 角标、
`TORONTO`、`LFC700 PRO`、`ONTARIO ... MUSEUM` 门楣、iPhone 界面上的 `Maya` / `iMessage` / `9:41`)。
**没有写任何"应该会有但我没看到"的词**。命中任意一条即算召回成功 —— 因为 OCR 只扫胶片条的 ≤12 帧,
要求它把一整条片子的字都认全是不公平的判据。

`BENDA` 角标 21 条真素材里**每一条都有**(常驻右下/正下),所以它是 OCR 这一项的**正控**:
连 `BENDA` 都召回不到,说明 OCR 整条链路没跑起来,而不是"这条片子字少"。

## 5. `speech` 的判据是"有没有烧录**对白**字幕",不是音量

全部 18 条真素材的音轨 `mean_volume` 都在 −17 ~ −29 dB 之间,**没有一条是静音**,
所以音量区分不出"有人说话"和"只有音乐"。判据改成:那一段里有没有出现对白字幕。

- `speech=1`(13 条):出现了成句的人物台词(例 `玛雅让我把这个交给你。` / `他先把车带走了。`)。
- `speech=0`(3+3 条):夜骑组 0820–0823 七个采样点一句台词都没有,只有 `BENDA` / `TORONTO` / `LFC700 PRO`
  这类**标板文字**——标板不是对白;DJI 三条根本没有音轨。
- `speech=*`(2 条,`IMG_0831_出门` / `IMG_0835_山路`):七个采样点没抓到字幕,但它们夹在两条有对白的素材中间,
  很可能只是采样点落在了台词之间。**没证据就不判**,不拿"没看见"当"没有"。

> 没有用 whisper 去生成参考转写:`whisper-cli` 的模型在 `~/Library/Application Support/TripCutStudio/models/`,
> 那是业主运行中的 profile,本轮规则不碰。所以本语料**不含转写 CER 指标**,只判"有没有口播"这一位。

## 6. `best_window` 是"我会剪进成片的那 3–4 秒"

一条 6–15 s 的素材里选一段,标准按业主的口径:**信息量最大**的那一段(有台词落点、
有人的反应、或者主体最清楚),不是画质最好的那一段。这正是要拿来打脸时刻分的地方 ——
时刻分现在的公式是 `0.30 清晰 + 0.25 运动适中 + 0.20 曝光 + 0.15 声音 + 0.10 无切换`,
五项全是画质,所以它大概率会挑中空镜(湿地面反光、轮毂特写)而不是这里标的这些窗口。
**基线报告里这一栏低才是对的**,不要为了让它好看去改真值。

判据:`IoU(建议段, best_window) ≥ 0.5` 算命中。`*` 的四条(DJI 三条 + 无)不计入分母。

## 7. `queries.tsv` 的 20 条怎么选的

一半 `narrow`(1–3 条相关,考精确)、一半 `broad`(4–12 条相关,考召回)。
覆盖了四类会打架的形态:

1. **物体级**(红色信封 / 摩托车头灯特写 / 摩托车轮毂细节)——clip 级均值向量最容易抹平的一类,
   预期 Recall@5 最低,正好是 AI-P1-7「搜索到不了第几秒」的量化位。
2. **场景级**(夜晚城市天际线 / 高速公路骑行 / 宴会厅内景)——clip 级向量应该擅长。
3. **人物属性**(白色头盔的女骑手 / 骑手正面肖像 / 两个人打招呼互动)——考 `person_state` 这一维有没有用。
4. **非内容**(彩条测试图 / 品牌片尾卡)——考"能不能把不该出现在成片里的东西挑出来"。

相关集是人工看帧标的,**允许一条素材出现在多条 query 的相关集里**(它们本来就是多镜头剪辑)。

## 8. 已知的语料短板(下一轮要补的)

- 没有 4K 真素材(只有合成彩条),也没有 HDR/10 bit 真素材。
- 没有横屏真实旅行素材(全是品牌片),`subject=食物` / `动物` / `商品` 三个标签**一条都没有**
  —— 所以八维里这三类的准确率这一轮测不了。
- `speech` 有 2 条没定;没有转写文本真值,CER 测不了(理由见 §5)。
- 节拍(BPM / beat)没有真值:这几条片子的音乐是成品混音,人工数不出可信 BPM。

## 9. 2026-09-14 首跑基线怎么读(`baseline-2026-09-14.md`)

首跑就是对照组本身,下面四条是**这一轮读出来的事实**,不是目标值:

| 指标 | 真素材 | 合成夹具 | 读法 |
|---|---|---|---|
| 八维 top-1(五维) | 未测量 | 未测量 | 本机没有本地 Chinese-CLIP 模型目录(`TRIPCUT_CLIP_MODEL_DIR` 没配、`~/Movies`/缓存里也找不到),侧车根本起不来 —— 这就是 AI-P1-10「正式包里 CLIP 大概率跑不起来」的实测一票。**「未测量」不是 0**,后面谁把它当 0 去对比都是错的。 |
| 画面搜索 Recall@5 / MRR | 未测量 | 未测量 | 同上。20 条 query 已经入库,CLIP 一备齐就能出数。 |
| OCR 关键词召回 | **2/18 = 11%** | 3/3 = 100% | 合成片的招牌常驻整条,随便抽帧都抓得到;真素材的字幕是**逐句换的**,而 OCR 只扫胶片条的 ≤12 帧 —— 21 条真素材总共只落了 7 行 OCR。这不是 Vision 认不出中文(0812 认出了「玛滩让我把这个交给你」、0837 认出了「BENDA / 夜向馆藏」),是**采样密度不够**。要提召回,改的是采样策略,不是识别器。 |
| 口播判定 · 负控 | **3/7 = 43%** | 5/5 = 100% | 夜骑组 0820–0823 四条**没有一句对白、只有音乐**,四条全被判成「有人声」。这是 `moments.rs:320` 那套「RMS > −30 dB 且峰均比 > 10 dB 就算人声」在音乐上必然误报 —— AI-P1 里 B-3「真 VAD 替掉峰均比」的直接证据。合成集测不出来:它的对照组是粉噪,峰均比根本不像人声。 |
| 时刻分最佳窗 IoU≥0.5 | **7/18 = 39%** | 2/3 = 67% | 预期之内(见 §6):现在的公式五项全是画质,选出来的常常是空镜。这一栏就是 AI-P0-2 / B-1 改完之后要对比的那个数。 |
| quick_hash 对得上 | 21/21 = 100% | 未测量 | 手上这 21 条就是被标注的那 21 条。合成片不判(每次重编码都不一样)。 |

**三条校准探针都红过了**(报告末尾「校准(先让它红过)」一节):期望词换成不存在的词 → OCR 召回掉到 0;
强制所有窗 `speech=false` → 口播召回掉到 0;真值窗平移 600 s → IoU 命中掉到 0。
指标不会红的指标不算指标 —— 这三条每次跑都重算,不是一次性的。

另外首跑抓到一个**假绿**并已修掉:第一版 harness 跳过了 `thumbnail` 任务,
而 `enqueue_missing_strips` 是按「有 cover 无 strip」筛的,于是胶片条一条都没排出来、
OCR 零输出 —— 可「OCR 负控(不该认出字)」当场给了 5/5 = 100%。空集让守卫失败朝开。
现在报告里多了一行「胶片条 / OCR 行」,零胶片条时 OCR 两格都不作数。
