## 它解决的不是剪辑，而是剪辑前的混乱

一次旅居或房车旅行，往往会留下相机卡、移动硬盘、手机和 NAS 中的大量零散片段。真正耗时间的，是重新看完素材、判断哪些镜头值得保留、找到故事主线，再把结果可靠地交给剪映。

TripCut Studio 是一个中文优先、Local-first 的 macOS 素材工作台。它不取代剪映，而是在剪映之前完成最费时间的整理工作：

- 引用式导入素材，原片保持只读；
- 自动分析每条素材最好看的一段，一键挑出整集的精选段，挑错可撤销；
- 播放、评级、收藏、拒绝和手动标记精选段，键位和剪映一致；
- 挑好的片段自动排进时间线化的镜头带，按章节整理顺序，拖边微调入出点；
- 快速导出精选片段、生成剪映草稿或剪映素材包，或生成可核对、可恢复的完整交付包。

## 为旅居和房车 Vlog 设计

| 旅途中的真实问题 | TripCut 的处理方式 |
| --- | --- |
| 素材散落在多个盘和目录 | watched folder 与引用式索引，不强迫搬运原片 |
| 一天拍几十条，没时间从头看到尾 | 每条素材自动标出最精彩的一段，选中就从那里开播，一键挑出整集精选 |
| 驾驶、驻车、做饭、风景混在一起 | 快速筛片、质量角标、精选段与 Shot Stack |
| 每一集都容易重复相似镜头 | Episode 封存与跨集素材记忆 |
| 在路上网络不稳定 | 核心整理、播放与交付均以本地工作流为主 |
| AI 建议可能不可靠 | 建议与人工确认分开保存，自动挑选可整批撤销，创作者拥有最终裁量 |
| 最终仍要在熟悉的软件里精剪 | 键位与剪映一致；一键生成剪映草稿或按顺序编号的剪映素材包 |

## v0.7.0 包含什么

### 四步流水线：导入 → 挑选 → 排列 → 导出

<p align="center">
  <img src="docs/screenshots/v0.7.0-workspace.png" alt="v0.7.0 工作台：顶栏四步导航与「下一步：导出」主按钮、监视器下的建议热力条、带时间刻度的镜头带与一次性引导气泡" width="100%">
</p>

0.5.0 之后我们又走了两轮：0.6 把散落的功能收成「一条流水线」，让新手一眼看懂自己在第几步、下一步该点哪里；0.7 在此基础上向剪映的使用习惯靠拢——键位、设置分区、引导方式都改成剪映用户熟悉的样子，再补上两条把片段交给剪映的路。

- **四步导航条**：顶栏中央是「① 导入 → ② 挑选 → ③ 排列 → ④ 导出」，当前在哪一步一眼看出，完成的步会打勾，点任意一步能直接跳过去；
- **「下一步：…」按钮**：顶栏主按钮随你走到哪一步换成「下一步：导入素材」「下一步：自动挑选」「下一步：排到镜头带」「下一步：导出」，永远告诉你现在该点哪里；片段全排好就直接进到导出，还有章没排满则给一个「补缺口」的次要动作；
- **首页**：第一次打开或点顶栏 logo 会看到首页——「新建一集」大按钮、「继续上次」与最近编辑过的集（模板入口在下一版做实后再回来）；
- **一次性引导气泡**：第一次用到导航条、自动挑选、镜头带、导出这些功能时，弹一句话的小气泡说明它是干什么的，点「知道了」不再出现；「设置 → 关于 → 重置新手引导」可重看；
- **剪映键位预设**：默认键位改成和剪映一致（空格播放、`I` / `O` 打入出点、方向键逐帧、`J` / `K` / `L` 走带、`⌘Z` 撤销、`⌘E` 导出），从剪映过来的人不用重新记；「设置 → 快捷键」可一键切成 Premiere Pro 或 Final Cut Pro 预设，也能逐个改；
- **剪映式设置**：设置页按剪映的分类整理成六块——「项目与缓存 / 快捷键 / 播放与导出 / 性能 / 工具与模型 / 关于」，每块顶部一句话说明"这里管什么"，所有选项摆在明面上，不再藏进「高级…」；另有一个偏冷偏暗的剪映风格深色主题可选（默认不开）；
- **时间线化的镜头带**：镜头带上方多了时间刻度和播放头（红线），播放时跟着画面走，点刻度或点片段直接跳转；片段可以拖动两侧边缘微调入点和出点，不用回监视器逐帧对；挑好的片段自动排进镜头带，「一键排入」可随时补排、整批撤销，「往前 / 往后」按钮不拖拽也能调顺序；
- **导入剪映继续剪**：镜头带和导出面板都能把整理好的片段交给剪映。剪映版本已核对过的机器直接生成草稿；还没核对的版本给一条**试验草稿 + 人工确认**的路——生成一份带「试验」字样、不碰你现有项目的草稿，你在剪映里开一次，回来点「可以用」或「打不开」，之后就按你的答案办；无论哪种情况都有**剪映素材包**：按镜头带顺序编号导出片段，附一份「顺序.txt」，拖进剪映时间线顺序就是文件编号。草稿用你的集名命名，每章第一个镜头带章节标记，配了背景音乐也会带上配乐轨；
- **分析更准**：曝光正常的夜景（路灯、窗户、手机屏这类高光）不再被误判成欠曝；三脚架和平稳跟拍不再被贴上「手持抖动」；场景硬切（尤其暗场之间）抓得更全；老素材库打开后会自动用新逻辑重新分析一遍；
- **缺失素材检测**：原片被移动或外置硬盘拔掉后，启动、关注文件夹同步、手动扫描、导出前都会真的检查文件还在不在，不在的卡片标「缺失」，导出时明确拒绝并说清是哪个文件；
- **真变速**：2 倍 / 4 倍速与反向逐帧改成原生变速播放，画面连续流畅，不再是"暂停后快速跳位置"的模拟；
- **更稳**：预览不再自动播放（按空格才播），「连播」是监视器上一个明确的开关；状态条估算「大约还要 X 秒」并与真实分析进度同步，不再卡在"正在分析 7/9"；只读查看旧集时镜头带和导出严格按那一集取数据；「只重试失败的」写回原文件夹、沿用原编号；自动挑选、撤销、排入、导出的结果都用顶部提示条告知。

### 键位（剪映默认预设）

以下是「设置 → 快捷键」里的剪映预设，也是本版默认键位；切到 Premiere Pro 预设时导出改为 `⌘M`、全屏改为 `` ` ``，Final Cut Pro 预设全屏改为 `⇧⌘F`，其余一致。

监视器（焦点在监视器栏时生效，`F6` 可把焦点送过去）：

| 键位 | 作用 |
| --- | --- |
| `Space` | 播放 / 暂停（在媒体池里也生效） |
| `J` / `K` / `L` | 倒退播放 / 暂停并回到常速 / 常速播放（`K` 在媒体池、镜头带上也能停播） |
| `←` / `→`（或 `,` / `.`） | 上一帧 / 下一帧 |
| `⌥←` / `⌥→` | ±1 秒 |
| `⇧←` / `⇧→` | ±5 秒 |
| `I` / `O` / `S` | 设入点 / 设出点 / 保存片段 |
| `⇧L` | 在入出点区间内循环播放 |

### 已知限制

- **剪映 11.4 的草稿需要你确认一次**：目前只核对过剪映 11.3.0 的草稿格式；本机是 11.4 时，导出面板会给「仍然试着生成（试验）」按钮，请在剪映里打开那份试验草稿后回来点「可以用」或「打不开」，之后才会默认直接生成草稿；不想试的话「剪映素材包」永远可用；
- 草稿里的配乐轨格式参考的是第三方资料，尚未与真实剪映草稿逐项比对，配乐读不出来时请反馈；
- Chinese-CLIP 画面语义检索与 Whisper 语音转写是可选增强，不随安装包分发，可在「设置 → 工具与模型」里下载安装；没装时"有没有说话"只按音量粗判；
- MiniMax「生成候选」补镜需自备 API key（设置 → 工具与模型 → 云端补镜，默认关闭，Key 只写入 macOS 钥匙串）；
- 首页的模板卡目前只会新建项目并打开导入，还不会真的按模板自动挑片、排镜头；
- 拖动片段边缘调整入出点后会生成新的片段记录，旧片段的星级不会自动带过去；
- 全新安装、从未激活过窗口的第一次启动偶发几十秒白屏（点一下窗口置前即可），日常从访达或程序坞打开基本不受影响；
- 状态条的「预计时间」目前只在几十条短素材上验证过，几百条长片上算得准不准还没测。

完整变更详见 [v0.7.0 更新说明](docs/releases/v0.7.0.md)；无人值守 QA 记录见 [R14 报告](docs/qa/2026-09-14-unattended-r14.md)。

0.3.0 发出去之后，我们请业主真实走了一遍全流程，0.4.0（未对外发布）修掉了 37 处卡点；这一版在那个基础上回答三个问题：软件能不能帮忙挑精选段、导出能不能更简单、播放器能不能更聪明。

- **时刻分热力条**：每条素材都会离线分析"哪一段最好看"（清晰度、运动幅度、曝光、有没有声音），选中后监视器进度条下方多出一条热力条，标出建议片段的位置与分数；

- **播放器**：逐帧前进 / 后退，`⌥←` / `⌥→` ±5 秒，打好入出点后 `⇧L` 循环反复看，播完自动接下一条（可关），静音状态跨素材记住，素材卡片上悬停鼠标就能看到动态预览；
- **设置三分区**：九个分类收进「常用 / 工具与模型 / 关于」，常用项摆在最前，不常用的收进「高级…」；
- **首启三步引导**：第一次打开不再是工具链检查清单，而是「导入素材 → 挑选片段 → 导出」三张引导卡片；
- **界面去术语**：内部代码名和技术缩写换成看得懂的说法，每个界面只保留一个最显眼的主要操作，错误与空白状态用一句话说清"发生了什么、接下来怎么办"。

## 产品边界

| TripCut 会做 | TripCut 不会做 |
| --- | --- |

| 为重复镜头、故事结构和交付提供辅助 | 替创作者决定事实与最终叙事 |

## 从源码开发

开发环境需要 macOS Apple Silicon、Node.js 22+、Rust stable 与 Tauri 2 所需系统工具。

```sh
npm ci
npm run typecheck
npm run lint
npm test
cargo test --manifest-path src-tauri/Cargo.toml
```

原生媒体组件与 DMG 构建顺序：

```sh
./scripts/build-lgpl-ffmpeg.sh
./scripts/build-libplacebo.sh
./scripts/build-lgpl-mpv.sh
./scripts/build-whisper.sh

TRIPCUT_PACKAGE_MODE=preview \
TRIPCUT_ALLOW_ADHOC=1 \
TRIPCUT_BUILD_STAMP=local-preview \
./scripts/package-dmg.sh
```

完整构建、签名、许可证与发布门禁见[发布说明](docs/RELEASE.md)。打包后的应用不依赖用户安装 Homebrew。
