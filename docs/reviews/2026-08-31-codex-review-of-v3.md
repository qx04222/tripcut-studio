## 1. 不同意的技术决断

- 🔴 「独立 Swift 进程 + NSView child-window」在进程模型上讲不通:helper 无法把自己的 NSView 直接挂进 Tauri 进程的 NSWindow。若实为两个顶层 NSWindow 伪装叠加,必然承受焦点、遮挡、Spaces、全屏、辅助功能同步问题——不是一次 spike 能消掉的尾部风险。
- 🔴 「整数 tick + 分数帧率」不能完整表示 VFR;必须保存源流 time_base、真实 PTS/帧索引映射。
- 🔴 导入时标记 VFR、切片时一律 `-fps_mode cfr` 会主动丢帧/补帧,破坏「帧级批注」和入出点语义;CFR 应是明确的导出策略,不是统一修复。
- 🔴 把 `-ss` 前置等同于帧精确不成立;必须回读首尾 PTS 验证。
- 🟡 「stream copy 关键帧吸附可接受」不能作为默认稳定包:长 GOP 可让边界偏移数秒;至少显示实际边界,超阈值自动转码。
- 🔴 草稿失败后「不报错」违背「可信任」:可以不中断,但必须明确显示降级原因、最终产物和缺失能力。
- 🔴 `running→pending + payload_hash` 不等于幂等;外部副作用需要 attempt ID、临时产物、原子提交和完成标记。
- 🟡 `VACUUM INTO` 同盘快照挡不住磁盘丢失,缺保留策略、恢复演练及迁移回滚。
- 🟡 头尾 4MB+size 指纹只能缩小候选,不能自动确认重关联;歧义时必须多段采样或完整哈希。
- 🔴 「P1 不依赖任何未验证技术」不实:播放器、任务恢复、外置盘、代理缓存和稳定包都依赖 P0 或尚未定义的集成行为。
- 🔴 「实施者只写码不跑测试」必须取消;作者不运行最小回归会把返工推迟到集成阶段。
- 🟡 「任务卡中途不改」不合理;应冻结目标与验收,允许通过变更记录修订实现约束。

## 2. 工作量被低估的任务

- P0 六 spike 一周 → 实际 2-3 周(低估 2-3 倍)。
- 播放器对撞覆盖全判据 ≥8-12 工程日。
- Stage1 实测还需人工真值/机型矩阵/冷暖缓存/失败分类(低估 2 倍)。
- 运镜启发式难点在标注集与阈值校准,3-5 倍于实现工时。
- 稳定交付包隐含取消/磁盘满/断盘/音画同步/部分失败恢复,3 倍于「几条 ffmpeg 命令」。
- skimming/Source Tape 牵动代理策略/预取/虚拟化,低估 2-4 倍。
- 原生草稿是每版本持续兼容工程,首建 1-2 周。
- 打包签名公证 2-4 周,不能拖到末期。
- 三家 CLI 路由层比单 provider 低估 2-3 倍。

## 3. 播放器立场

明确倾向 **libmpv render API**(宿主渲染面内工作,避开跨进程伪 child-window 的结构性脆弱;FFmpeg 兼容面广;mpv 自带帧步进/事件模型;IINA 是产品级先例)。AVFoundation 保留为「独立播放器窗口」备选。
未讨论风险:libmpv 硬解不自动保证;mpv 默认构建 GPL,商业分发需 `-Dgpl=false` LGPL 构建+动态链接义务核验;libmpv2-rs 维护度/C ABI 生命周期/GPU context 重建未设门槛;两案共同遗漏 10-bit/HDR/色彩空间/旋转元数据/HiDPI。

## 4. 任务卡应包含(16 项模板)

任务ID+阶段+依赖与前置结论 / 用户可观察目标 / 范围与非目标 / 承重假设与杀停条件 / 接口与数据契约 / 数据不变量与迁移 / 状态机(idle/running/cancelling/failed/degraded/recovering) / 真实测试夹具 / 量化验收标准(基准机型+冷热缓存+p50/p95) / 验证责任与命令(真退出码) / 失败注入与恢复验收 / 依赖与分发约束 / 回滚与清理 / 交付证据(SHA+测试结果+基准数据+已知风险) / 变更记录(冻结目标非冻结文字)。

## 5. 方案缺失章节

支持矩阵 / 媒体兼容矩阵 / 色彩正确性 / 数据库演进(schema version) / 原子写入与容错 / project.db 异盘备份 / 安全与隐私(loopback 令牌、L3 出境数据清单) / macOS 权限模型(security-scoped bookmark 等) / 依赖许可证与 SBOM / 性能预算细化 / 测试策略分层 / 升级与回滚 / 并发所有权(多实例互斥) / 缓存治理 / 模型可追溯性。
