### 2.3 判据
- 新工具 `fpsprobe`(scratch):ScreenCaptureKit 抓应用窗口,**同一张截图**里解条码帧号 + 找进度条红色竖线指针的亚像素 x;另一线程按 25 ms 读 AX「播放位置」滑杆值、「当前时间码」AXHelp、播放 / 暂停按钮。命令序列取 `TRIPCUT_LOG=debug` 的 `player command` 行;mpv 细节取 `TRIPCUT_MPV_LOG_FILE`。
- 指针 → 秒:完整视图按 AX 滑杆 frame 几何映射、原点用最终暂停态(指针与 AX 同源)校准;放大视图用两个暂停态(选中后停点、出点停点)的 (x, AX 位置) 线性拟合。**完整视图 60 s 素材 1 px ≈ 36.8 ms,60 fps 下 1 px ≈ 2.2 帧,分辨率本身就不够判 ≤1 帧**,所以指针精度以放大视图为准。
- 选段操作用 AX 按镜块(= 点镜块中部,停在中部位置),按「播放」到出点停;停住后再按「播放」= 从入点重播(第二段测入点)。
- 环境:隔离 profile、更新端点死端口、按 pid 置前,窗口固定在外接屏 (−2500, 40) 2400×1340(默认宽度下「连播」开关被收起,见 O-2);真机段持 `realmachine.lock`,写码 / 门禁期间已释放。**测试期间业主在用电脑**:窗口被最小化一次(状态轮询停、播放卡住,那一轮作废)、被缩小一次(条码定位失败,那两条重跑);之后每轮开跑前脚本先复原窗口。

## 4. 缺陷与修复

### F-1(P1)HEVC 素材选段停在出点后,时码 / 红指针跳回约 1.1 s —— 已修 `c51aafe`
- 现象:画面停在出点前最后一帧(对),但时码与指针显示 ~1.1 s 之前(29.97p 画面 15.98 / 时码 14.805;59.94p 10.98 / 9.899;50p 13.98 / 12.864)。基线截图:画面「15」秒、时码 `00:14.24`。
- 根因:`usePlaythrough` 到出点后 `pause()` 再 `seekTo(out − 1/fps)`(这一步是 R22 没有围栏时用来回拉越界的)。open-GOP HEVC 的出点前一帧是 CRA 的前导帧,**带着 `end` 围栏**的 exact seek 让 mpv 的 `time-pos` 报成前一个 GOP 里的位置、画面不动。mpv 0.41 CLI 同文件复现:不 seek → `time-pos=16.0`、截图第 479 帧;带围栏 seek 15.9666 / 15.9826 → `time-pos=14.827`、截图仍 479;撤围栏再 seek → 截图第 480 帧(出点帧,越界)。H.264 不受影响。
- 修复:只有真越界(`pos > out + 半帧`)才纠偏;围栏正常停住就保留 mpv 停的那一帧与位置。「停在出点按播放 = 从入点重播」不变。
- 先红后绿:`usePlaythrough.test.tsx` 新 5 条(围栏停在 out 不 seek;−1.5 / −1 / 0 / +0.5 帧不 seek、+1.1 帧仍回拉)在基线源码上 **5 红** → 绿。真机见 §3 表。

### F-2(P2)播放中指针落后画面 2–6 帧 —— 已修 `dd14ae8`(部分达标)
- 新 `src/workspace/scrubber/useDisplayPosition.ts`:显示位置 = 最近状态 `pos` + 收到后经过时间 × 倍速,`requestAnimationFrame` 推进;钳在 `min(活动出点, 时长)`,不低于 `pos`;暂停、未 ready、定位命令未返回、倒退、换段中、clip 不符时直接用实际 `pos`;每份新状态重锚。指针(完整 / 放大)、数字时码、`aria-valuenow/valuetext` 共用这一个值;所有命令目标仍用真实状态;80 ms 轮询不变;不写 store。

### F-3(P1,R26 P-1 回归)连播「下一段」卡 2 s —— 已修 `920b1ed`
- 根因:当前输出设备「MacBook Pro 扬声器」上 coreaudio 设声道布局一律失败(`unable to set the input channel layout ... -50`),**立体声 / 单声道 / `audio-channels=stereo`(R26 的修法)/ `=2` / `auto-safe` / `unknown2` 全部**回退 `ao/avfoundation`(48 kHz soft-buffer 96000 = 2 s)。带 `end` 围栏播放时音频先撞 EOF,`pause=yes` → `ao_drain` 等缓冲放完。R26 在 coreaudio 能打开的设备上测,所以当时 0 ms。CLI:默认 1985–2047 ms;`--ao=coreaudio` 独占 → 无声(不可用);先 `end=none` 再暂停 → 仍 ~2 s;**先 `ao-reload` 再暂停 → 44–51 ms**。
- 修复:新 `player/pause_drain.rs`,执行 Pause 时若「未暂停 + 围栏已设 + `current-ao=avfoundation` + `time-pos ≥ end − 4 s`」先 `ao-reload`(失败只 warn)再 `pause`;`SetEnd` 成功才记录围栏值。`audio-channels=stereo` 保留。
- 先红后绿:接线顺序测试在基线源码上 **panic 红** → 绿;纯函数 4 条覆盖 coreaudio / 无围栏 / 离围栏远 / 已暂停不 reload。真机见 §3 表。
