## 4. 修复

### S-1 取源规则(`4ea8e07`)
- **自动档 × 标准机**:播放、暂停都读原片。本机盘原片打开时当场核验(只快速哈希);外置盘原片(`rel_path` 相对路径,核验要整文件哈希)仍先开代理、后台核验完**在播放中也换原片**。
- **自动档 × 省内存 / 低配机**:保持「播放代理、暂停原片」,播放优先 1080p 高清代理,没有才 540p。
- **掉帧退路**(`player/drop_watch.rs`):原片播放起步 3 s 宽限后,**6 s 内掉 ≥30 帧(50p 下 10%)且分散在 ≥4 个不同的秒里** → 本次改播代理(1080p 优先,暂停仍原片);**退到代理后代理照样持续掉帧 → 回原片且本次不再降级**。定位 / 换源 / 恢复播放都重新计宽限。
  - 为什么不是「3 s 内 ≥15 帧」(初版):真机见 §5.3,别的程序抢 WindowServer 时 0.3 s 内一口气掉 15 帧,**1080p 代理在同一时刻也一样掉** —— 那是整机卡,不是解不动原片,降成代理只丢清晰度换不来流畅。
- 状态新增 `auto_policy`(`original` / `proxy` / `degraded`)。角标:标准机自动档只写「原片 2160p」,省内存机暂停写「· 暂停看原片」,退代理时写「代理 1080p · 原片掉帧,改播代理」。自动档不再弹「原片播放掉帧 / 改用代理播放」(播放器自己处理);原片档掉帧点「改用代理播放」→ 切回自动时立即按掉帧处理。
- 设置「预览画质」自动档:「自动(推荐):看原片,掉帧才改播代理」;说明同步改。性能优先 / 高画质 / 原片三档行为不变。
- 术语白名单:`PerformanceSection` 那条正则 `播放用代理` → `改播代理`;`previewSource.ts` 新增一条(「原片掉帧,改播代理」),理由写在条目里。

### S-2 best-resolution(`2645b01`)
嫌疑 2 证伪,但 `render_frame` 依赖「drawable = backing 像素」这一前提,原先只靠链接期默认值。`build_surface` 在挂进窗口前显式 `setWantsBestResolutionOpenGLSurface(true)`,源码门禁钉住顺序。

- 采样期间业主机忙:`WindowServer 85% CPU`、`replayd`(录屏)、`SkyComputerUseService 34%`、`fileproviderd 100%`。

## 6. 拍板记录
- **自动档的「标准机」口径 = 非省内存(`low_memory_proxy()` 为假:Standard / HighPerf)**。16 GB 机器(Low 档)保持「播放代理、暂停原片」—— 任务书写「low_spec / 低内存」都退代理。
- **本机盘原片当场核验,外置盘延后**:本机盘只做快速哈希(毫秒级);外置盘整文件哈希会把打开拖几秒,仍先开代理、核验完播放中换原片(换源实测 75–233 ms)。
- **掉帧降级只在本次打开内有效**,换素材重新判:业主机实测 4K50 原片 0 掉帧,偶发卡顿不该让后面所有素材都糊。
- **「代理也掉帧 → 回原片」**:任务书只写了「掉帧才退代理」,真机证明整机卡时退代理不解决卡顿、只丢清晰度,按「业主日常最顺」加这一条。
- **不换缩放滤镜**:测量显示原片档文字锐度 ≈ lanczos 参照(0.923 / 1x 屏 1.026),默认已是 lanczos/hermite + 线性光缩小;任务书建议的 `dscale=mitchell` 比 hermite 更软,没有依据就不动。
- **没派 Codex**:改动集中在一个已读透的状态机,测量—改—再测量的循环比写任务书更快;公共约定里的门禁、先红后绿、提交格式照做。
