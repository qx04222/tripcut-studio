## 1. D-1 字幕写进时间线

### 1.1 行为
- 抽屉「剪映草稿」一行里,在剪映可用(`supported`)或允许试验生成(`force_allowed`)时出现子开关 **「字幕写进时间线(试验)」**(新 AX:role `switch`,名 `字幕写进时间线(试验)`;常量 `SUBTITLES_ON_TIMELINE_LABEL`)。默认关,不持久化(每次打开抽屉都是关)。普通生成与「仍然试着生成(试验)」两条路都带上它。
- 开:每个精选段的原片时间码 SRT(与 `TripCut字幕/` 拷的是同一份文件)→ 只留与段 `[入点, 出点)` 相交的部分 → 平移「段在时间线上的起点 − 入点」→ 写成一条剪映文字轨「TripCut字幕」(插在视频轨之后、配乐轨之前)。同一轨不能重叠,原片里互相重叠的字幕后一条开头截到前一条结尾;截完或按毫秒取整后为空的丢弃。同时在 `TripCut字幕/时间线字幕.srt` 写一份**与文字轨同一张 cue 表**的时间线 SRT;原来的逐段原片时间码 SRT 照常输出;`TripCut交付说明.txt` 换成「已写成文字轨(试验,共 n 条)」的说明。
- 开但没有一条字幕落进精选段(或本集没转写):不建空文字轨、不写时间线 SRT,草稿同 0.11.4。
- 结果 `JianyingDraftResult` 新增 `subtitles_on_timeline` / `timeline_subtitle_count`;结果卡(普通与试验两种)开时多一行「字幕已写进时间线:n 条(试验,请在剪映里核对位置与断句)」。manifest 只在开时追加这两个键。
- tauri 命令 `generate_jianying_draft` 新增可选参数 `subtitlesOnTimeline`,缺省 = 关;前端关时的 `invoke` 调用与旧版逐字相同(无第二参数 / `{ force: true }`)。

## 2. D-2 章节标记:查过的来源与不做的理由

要找的是剪映自己写出来的**非空** `time_marks` 元素(`materials.time_marks[]` 或顶层 `time_marks`)。

| 来源 | 结果 |
|---|---|
| pyJianYingDraft 0.1.5 / 0.2.7 / 0.3.0(三个 wheel 全文 grep) | 只有模板里的 `"time_marks": []`(materials)与 `"time_marks": null`(顶层)(`assets/draft_content_template.json:104,120`、`script_material.py:140`);不建模元素 |
| `gh search code '"time_marks"'`(50 条)+ `"time_marks" mark_items` / `mark_items jianying` / `mark_items capcut`,约 60 个仓库:VectCutAPI、capcut-mate、pyCapCut、NarratoAI、capcut-cli、jianying-headless、JyDraft(C#)、Storyboard(C#)、qcut(含 jianying-macos-11.3.0 / CapCut 8.1 金样 profile)、hotclip、CutPilot、video-recap-skills 等 | 全部是 `[]` / `null` / `{"id":…,"mark_items":[]}`,**没有一个非空元素**;qcut 自己的文档明说本地样本为空、不能断言支持 |
| Sleeve.ai `capcut_draft.py`(称逆向自真实工程,CapCut 8.3.0 macOS) | 顶层是 `{"id", "mark_items": []}` 对象(不是 null),`mark_items` 仍为空 |
| chukfinley/chukcut `docs/research/draft-format.md`(2 星,2026-09-16) | 唯一给出非空形状的来源:`{ id, mark_items: [ { id, title, color, time_range } ] }`,示例 `{"title":"Marker 01","color":"#00c1cd","time_range":{"start":2900000,"duration":0}}`;但它是 **CapCut 9.0.0.3858 Windows** 的 markdown 转述,仓库里没有原始 JSON,不是剪映 11.x macOS |

**不做的理由**:① 唯一的非空形状来自另一个产品线(CapCut 国际版 Windows 9.0)的二手文档,无原始 JSON 可逐键核对;② 11.3.0 金样里顶层 `time_marks` 是 `null`,而 CapCut 样本里是对象——连「标记写在顶层还是 `materials.time_marks`」都对不上,照它写就是猜;③ 现有注释(`jianying.rs` 章节标记处)已记录「猜结构会让剪映拒开整份草稿」,且本机剪映 11.4 草稿加密,无法自证。保持现有「【第 n 章·章名】」素材名前缀,不写代码。scratch 里留了三份原文(`timemarks/`),下轮若拿到剪映 11.x 自己导出的带标记草稿(业主在剪映里手动打一个标记、另存一份明文草稿即可),再按 D-1 的「默认关开关 + 白名单」思路做。
