# R5 音乐节奏 + OCR Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用户导入一首音乐得到节拍/强拍/段落/高潮/建议切点（只建议不改写）；素材画面文字（招牌、票据）用 macOS Vision 离线识别并进入全量搜索第五路。

**Architecture:** 音乐：纯 Rust（rustfft）短时 FFT → 频谱通量 onset → 自相关/梳状滤波 BPM → 能量+质心分段 → 高潮启发式；ffmpeg 解码到 PCM（复用波形任务的解码参数）；`music_tracks/music_beats/music_sections`（迁移 0034）；job kind `music_analyze`。OCR：独立 Swift 命令行工具 `sidecar-ocr`（Vision `VNRecognizeTextRequest`，zh-Hans+en），随包走 whisper-cli 同一套嵌入/签名/SBOM 步骤；抽帧复用胶片条（strip 的 12 帧）；`clip_ocr_texts`（迁移 0035）；job kind `ocr_scan`；`search_everything` 第五路 `kind="ocr"`（LIKE，与现有四路一致）。

**Tech Stack:** rustfft（MIT，锁版本）、ffmpeg `-f s16le -ac 1 -ar 22050`、Swift 6.4（CLT 的 swiftc 可编译，`-framework Vision -framework AppKit`）、rusqlite、React canvas。

### Task 1: 0034 音乐数据层 + 纯 Rust 节拍分析

**Files:** `migrations.rs`（`MIGRATION_0034`：表 `music_tracks(id, episode_id, file_name, rel_path, quick_hash, duration_ticks, tb_num, tb_den, bpm REAL, analysis_status CHECK IN ('pending','running','done','failed'), created_at)`、`music_beats(track_id, tick, is_downbeat, strength)`、`music_sections(track_id, start_tick, end_tick, label CHECK IN ('intro','verse','build','climax','outro','other'), energy)` + 两索引）、`Cargo.toml`（`rustfft = "=6.x"`）、新 `src-tauri/src/core/music.rs`
**Interfaces:**
```rust
pub struct BeatGrid { pub bpm: f64, pub beats_ticks: Vec<i64>, pub downbeats_ticks: Vec<i64>, pub strengths: Vec<f32> }
pub struct Section { pub start_tick: i64, pub end_tick: i64, pub label: SectionLabel, pub energy: f32 }
pub fn analyze_pcm(samples: &[i16], sample_rate: u32) -> Result<(BeatGrid, Vec<Section>, Vec<i64> /* suggested cut ticks */)>;
pub fn decode_pcm(ffmpeg: &OsStr, path: &Path) -> Result<(Vec<i16>, u32)>;   // -vn -ac 1 -ar 22050 -f s16le -
```
- [x] 失败测试（合成信号，不依赖真实音乐）：120 BPM 点击音轨（每 0.5 s 一个 10 ms 白噪声脉冲，60 s）→ `bpm` 在 118–122；`beats_ticks` 间隔中位数 ≈ 500 000；纯静音 → 无 onset、`bpm` = 0 且 Err「未检测到节拍」；能量阶梯信号（低→高→低）→ 至少 2 个段落边界、中段 label 为 `climax` 或 `build`；90 BPM 与 120 BPM 混合两段 → 报告前半/后半 bpm（如实现按窗口估计）。
- [x] 实现：帧长 2048、跳 512、汉宁窗；通量 = Σ max(0, |X_t| − |X_{t−1}|)；BPM 用 60–200 范围自相关峰；下拍 = 每 4 拍取通量最大者；段落 = 通量/RMS 8 秒滑窗方差的跳变；切点 = 下拍 ∪ 段落边界。
- [x] Commit：`feat(music): 迁移 0034 与纯 Rust 节拍/段落分析(rustfft)`
