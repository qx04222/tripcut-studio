# R16 「人需要的都有入口」+ 低配机与性能(0.8.0)

业主原则(2026-09-14 晚):**凡是人需要做的操作(删除、设置、改名、移动…)必须在 UI 上有入口,不能因为「后台代码能做」就不做界面**;并要**支持配置稍低的电脑 + 性能优化**。
依据:`.superpowers/sdd/r16/brainstorm-ui-coverage.md`(161 条命令 / 全部设置键 / 用户数据表逐一对照,P1–P3 表)与 `.superpowers/sdd/r16/brainstorm-lowspec-perf.md`(实测,待到)。

## 1. 统一交互模式(先定规则,再铺实体)

- **每个实体一个「···」/ 右键菜单**,同一实体在不同栏里菜单项完全一致(kit `Menu` 已有):
  - 素材卡(媒体池 / 检查器头):收藏 · 拒绝 · 清除评级 · 加入镜头带 · 导出所选… · 在 Finder 中显示 · 移除素材…(多选时项目名带 `(n 条)`)
  - 镜块(镜头带):往前 · 往后 · 从镜头带移出 · 删除精选段 · 导出这一段…
  - 章头:重命名 · 并入上一章 · 这章够了 / 还是要镜头 · 删除这一章…
  - 集(切集弹层 / 首页卡):重命名 · 结束本集 · 只读查看 · 删除这一集…
  - 后台任务行:取消;状态条:全部暂停 / 继续
- **可逆操作不弹确认,出 5 秒 toast「撤销」**(拖排/忽略缺口/删精选段/移出镜头带/批量评级/并入上一章);**不可逆才弹确认卡**并列出后果数字(移除素材、删章、删集、删文件)。
- **批量 = 同一菜单项 + `(n 条)`**;热键在多选非空时作用于整组。
- 统一 ⌘Z 栈:拖排 + 叙事修改 + 批量评级(记旧值回写)。
- 规则写进 `docs/design/design-system.md` §6 并冻结。

## 2. 铺开(三条车道并行)

**车道 A · 接现成命令(前端为主)**:P1-1 移除单条/选中素材(复用导入页 `alertdialog` 后果预览)、P1-2 删精选段可撤销(`restore_select_segment`)、P1-4 从镜头带移出(`set_story_order` + `undo_story_change`)、P2-2 ⌘Z 接叙事撤销、P2-5 重新计算时刻分 / 重新识别画面文字(设置 › 工具与模型)、P2-8 导出文件夹「清除」、P2-9 缺失页「这个盘不会再回来了…」→ 移除预览、P2-11「重置新手引导」连四步提示一起清、P2-12「恢复默认布局」、P2-13「复制诊断信息」(只带版本/工具链/内存档/最近 3 条错误摘要,不带路径)。
**车道 B · 章节与批量(前端 + 少量 Rust)**:P1-3 章节内联改名、P1-5 多选批量评级/收藏/拒绝/清除(新 `rate_clips` 批命令 + 热键作用于多选 + 撤销回写)、P2-1 并入上一章 / 删除这一章(新 `delete_chapter`,镜移到相邻章,确认)、P2-3 任意集改名(`rename_episode(id)`)。
**车道 C · 新 Rust 命令 + 各自 UI**:P1-7 `relink_clip(clip_id, path)`(校验同名 + 时长;缺失页每条「找到它…」+ 检查器头)、P1-6 后台任务行「取消」(`cancel_job` 接线)+ `set_jobs_paused` 全部暂停/继续(状态条)、P2-4 `retry_clip_analysis(clip_id)`(检查器「重新分析这条」)、P2-6 `delete_display_lut` / `delete_whisper_model`(确认)、P2-7 `reveal_clip`、P2-10 `add_tag` / `remove_tag`(`tags.source='user'`,检查器标签段真能加删)。

## 3. 低配机与性能(brainstorm B 实测结论,Wave 1 两条车道)

**车道 D · 最低系统版本(P0)**:发布包里的 ffmpeg / libmpv / whisper / libplacebo / sidecar-ocr 全是 `minos 27.0`(Homebrew libass/glib 为 26.0),而 tauri.conf 声明 14.0 —— 现在的 DMG 实际只能在 macOS 27 上跑。五个 `scripts/build-*.sh` 都没设 `MACOSX_DEPLOYMENT_TARGET`,`audit-dmg.mjs` 也不查 minos。做法:先加审计门禁 `app.min-os-version`(对今天的包必须先红);所有原生构建统一 `MACOSX_DEPLOYMENT_TARGET=14.0`;Homebrew 来的依赖(libass、glib 等)要么从源码以 14.0 目标静态构建进来,要么换掉;重建后 `otool -l` 逐个 Mach-O 校验 ≤ 14.0;没有 macOS 14/15 真机时在报告里写清「只验证了 minos,未真机运行」。
**车道 E · 低配档与性能 Wave 1**:① 自动档 v2:现在 `auto` 以 24 GiB 为界,8 GB 与 16 GB 同档;新增 ≤8 GiB「省电/低配」档(4K 并发 1、≤1080p 并发 2、不借闲置解码槽、Whisper 默认 small、不起 OCR/CLIP 侧车),设置 › 性能 白话开关,用 `TRIPCUT_MEMORY_BUDGET_BYTES` + R15 4K 夹具验证;② 内存压力探测改读 `kern.memorystatus_level`(应用现在读到 24–28% 而系统实际 50–54%),保留 15/25 滞回;③ 预览小文件策略:≤1080p H.264 8-bit 不生成(实测 540p 预览比 720p 原片还大),预览文件缓存上限 + LRU;④ 前端:2 s 轮询每次新建 `feed` 对象导致订阅者全量重渲染 → 引用稳定 + `React.memo(PoolCard)`;⑤ 散热:`NSProcessInfo.thermalState` 三档退避 + 「只在空闲时做后台工作」开关;⑥ mpv 低配参数(`demuxer-max-bytes` 64 MiB、`scale=bilinear`)。
**Wave 2(需真机/大工程,不做)**:M1 8 GB Air 的散热/4K 播放验证;x86_64 估 3–5 天,建议不做。

## 4. 风险控制

- 无迁移(新命令只读写既有表;`tags.source` 已有列);破坏性操作全部走确认卡或撤销 toast;`remove_imported_material` 复用现有安全路径。
- 每车道独立文件;菜单项文案与 AX 名先在 §1 定死,三车道共用 `src/workspace/copy.ts` 追加;门禁 + 真机 10 分钟脚本(§5)。

## 5. 验收

真机:删一条素材(确认卡有后果数字)→ 删精选段后撤销 → 章头改名 → 移出镜块后撤销 → ⇧多选 10 条按 X 全拒绝再 ⌘Z → 取消一个运行中的任务 → 缺失页「找到它…」重连一条 → 「复制诊断信息」内容不含路径;门禁全绿。

## 6. R17 入口(本轮明确不做,留作下一轮候选)

- **AI 标签隐藏列**:车道 rust 报告已记录——`tags` 表没有隐藏列,`ai_l3` 行是 `ai_descriptions.tags_json` 的投影,每次重新生成会整组替换;本轮只做到"用户标签可删、AI 标签不可删"。真正的"只隐藏"需要加 `tags.hidden` 列(本轮 §4 明确无迁移),或改成删 `tags` 行而留 `ai_descriptions` 副本(但搜索/镜头组/资产安全都按 `tags` 拼关键词,语义不干净,不建议)。R17 视排期加列。
- **素材跨集移动**:调研 `brainstorm-ui-coverage.md` 提到但本轮未排入三车道任何一条——素材目前只能停留在导入时所在的集,没有"把这条素材挪到另一集"的入口。
- **x86_64 决策**:车道 minos 调研 §1.2 估算 3–5 天工作量,本轮建议不做;是否要做需要业主拍板(是否还有 Intel Mac 用户)。
- **深色主题打磨**:R13 的"剪映风格深色"主题只做了 27 个必须重定义令牌的基本覆盖,未做视觉遍历(规格 §0 一贯不做深色走查);R17 若要发布级质量需要专门一轮。
- **旧壳删除**:`MissingMediaPanel` 等 R9/R10 起标记"等删旧壳时一起消失"的旧组件仍在代码里,本轮未清理。
- **Wave 2(需真机/大工程)**:M1 8 GB Air 的散热/4K 播放真机验证(本轮车道 perf 只在开发机上用注入文件模拟三档热限流与内存压力,未在真正的低配设备上跑过);macOS 14/15 真机跑一遍车道 minos 的包(车道报告 §5 已写好 10 分钟步骤,等业主找到合适机器)。
